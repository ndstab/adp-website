# ADP Solutions website

Bilingual corporate website for **Advanced Digital Pathway Solutions** (ADP Solutions), Riyadh. Arabic is the default language (`/ar`, right-to-left); English is at `/en`.

Built with Next.js 16 (App Router), TypeScript, Tailwind CSS 4, next-intl, MDX and a small amount of Framer Motion. Every page is pre-rendered as static HTML (84 pages), and the only server-side code handles the three forms.

- Launch checklist: [`docs/LAUNCH-CHECKLIST.md`](docs/LAUNCH-CHECKLIST.md)
- Every `[ADD]` / `[CONFIRM]` / VERIFY marker in the content: `docs/REVIEW-ITEMS.md`, generated by `npm run review -- --write`
- Build history and decisions: `docs/PLAN.md`

Both of those, and `reference/`, are kept out of version control.

---

## 1. Run it locally

Requires **Node.js 20.9+** (developed on Node 24). This Mac has Node installed at `~/.local/node`; either add it to your shell or install Node from nodejs.org:

```bash
export PATH="$HOME/.local/node/bin:$PATH"
```

```bash
npm install
npm run dev
```

Open http://localhost:3000. It redirects to `/ar`.

| Command | What it does |
|---|---|
| `npm run dev` | Development server with hot reload |
| `npm run build` | Production build; also validates every content file |
| `npm start` | Serve the production build |
| `npm run lint` / `npm run typecheck` | ESLint / TypeScript |
| `npm run review` | List every review marker in `/content` (`-- --write` saves `docs/REVIEW-ITEMS.md`) |
| `npm run generate:og` | Rebuild the social-share image from the logo |

## 2. Environment variables

Copy `.env.example` to `.env.local` (development) or set them on your host.

| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | Public URL, e.g. `https://adpway.com`. Used for canonical links, hreflang, sitemap and structured data. |
| `NEXT_PUBLIC_REVIEW_MODE` | `true` (default) shows dashed **VERIFY** markers **and keeps the whole site out of search engines** (`robots.txt` disallows all, pages are `noindex`). Set to `false` for launch. |
| `CONTACT_TO_EMAIL` / `CONTACT_FROM_EMAIL` | Where form submissions go, and the sender address |
| `RESEND_API_KEY` | Send forms through Resend, **or** |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | send them through any SMTP server |
| `NEXT_PUBLIC_ANALYTICS_SCRIPT_URL`, `NEXT_PUBLIC_ANALYTICS_DOMAIN` | Optional analytics script. It loads only after a visitor clicks **Accept analytics**. |

`NEXT_PUBLIC_*` values are baked in at build time, so rebuild after changing them. With no mail settings, development prints submissions to the terminal and production returns an error to the visitor, so forms never fail silently.

## 3. Editing content

All text lives in [`/content`](content); components contain no copy. Every file is validated against a schema in [`src/content/schema.ts`](src/content/schema.ts), so a typo or a missing field fails `npm run build` with a clear message instead of publishing a blank section.

| What | Where |
|---|---|
| Company facts (phone, e-mail, CR, VAT, address, social links) | `content/site.json` |
| Market statistics and their sources (footnotes) | `content/sources.json` |
| Navigation, footer, form messages | `content/{ar,en}/common.json` |
| Homepage | `content/{ar,en}/home.json` |
| The 5 pillars | `content/{ar,en}/pillars.json` |
| Solution cards / full solution pages | `content/{ar,en}/solutions.json` / `content/{ar,en}/solutions/<slug>.json` |
| Industry cards / full industry pages | `content/{ar,en}/industries.json` / `content/{ar,en}/industries/<slug>.json` |
| FAQ | `content/{ar,en}/faq.json` |
| About, Our Model, Vision 2030, Compliance, Alliance, Careers, Contact, Insights labels | `content/{ar,en}/company.json` |
| Privacy, Terms, Cookies, cookie banner | `content/{ar,en}/legal.json` |
| Section labels on solution / industry pages | `content/{ar,en}/pages.json` |
| Insight articles | `content/insights/{ar,en}/<slug>.mdx` |

**Always edit both languages.** Arabic and English files have the same structure; keep them in step.

**Review markers.** Write `[ADD]` for information still to be supplied (it renders as a visible `[ADD]`). Set `"verify": true` on an outcome or statistic, or put `<Verify />` in an article, to show a dashed VERIFY marker while review mode is on. Run `npm run review` to see what is still open.

**Rules that apply to all copy:** no partner company or product names anywhere (copy, alt text, file names, code comments); no invented clients, testimonials, certifications or headcounts; "aligned to" / "supports compliance with" rather than any claim of NCA, SAMA, CST or SDAIA licensing; every market figure footnoted; every outcome described as typical.

### Add a solution or industry

1. Add a summary entry to `content/{ar,en}/solutions.json` (or `industries.json`) with a new `slug`.
2. Create `content/{ar,en}/solutions/<slug>.json` with the full page (copy an existing one as a template).
3. Update the count in `src/content/index.ts` (`.length(13)` / `.length(8)`), which guards against a half-added entry.
4. `npm run build`. The page, sitemap entry and hreflang links are generated automatically.

### Add an insight

1. Create `content/insights/en/<slug>.mdx` and `content/insights/ar/<slug>.mdx`, each starting with an `export const metadata = {title, excerpt, date, readMinutes, image, imageAlt}` block (see an existing article).
2. Add the slug to `insightSlugs` in `src/content/insights.ts`.
3. Articles show a "Draft" badge; remove it in `src/app/[locale]/insights/` once articles are approved.

## 4. Images and logo

- Photography is placeholder (free-licence). [`public/images/README.md`](public/images/README.md) lists every file, where it appears and what should replace it. **Keep the same file name** and roughly the same aspect ratio, and no code changes are needed. Update the matching `imageAlt` text in the content files.
- Logo files are in `public/brand/` (`adp-logo.png`, `adp-logo-white.png`, `adp-mark.png`, `adp-mark-white.png`; originals in `source/`). When a vector logo is available, replace these and update the `src` in `Header.tsx` / `Footer.tsx`. Then run `npm run generate:og` and replace `src/app/icon.png` / `apple-icon.png`.
- Images are served through `next/image` (AVIF/WebP, responsive sizes). Put new photos in `public/images/`; there is no need to pre-resize.

## 5. Deploying

The build is `output: "standalone"`: a self-contained Node server.

### Vercel

Import the repository, set the environment variables above, deploy. No extra configuration.

### Saudi-region host (Docker)

```bash
docker build -t adp-website \
  --build-arg NEXT_PUBLIC_SITE_URL=https://adpway.com \
  --build-arg NEXT_PUBLIC_REVIEW_MODE=false .
docker run -p 3000:3000 --env-file .env.production adp-website
```

The image runs as a non-root user on port 3000 with a health check on `/ar`, and is suitable for any container host in an in-Kingdom cloud region. Put it behind a TLS-terminating proxy or load balancer. The Dockerfile has **not** been built on this machine (Docker is not installed here); run the build above once in CI or on the target host before launch.

### Without Docker

```bash
npm ci && npm run build
cp -r public .next/standalone/ && cp -r .next/static .next/standalone/.next/
cd .next/standalone && PORT=3000 node server.js
```

### Production notes

- Security headers (CSP, HSTS, X-Frame-Options, Referrer-Policy, Permissions-Policy) are set in `next.config.ts` for production builds. If you add a third-party script or font host, add its origin to the CSP there.
- The form rate limiter is in-memory per server instance. With several instances, swap it for a shared store (`src/lib/rate-limit.ts`).
- `robots.txt`, `sitemap.xml`, canonical/hreflang tags, Open Graph images and schema.org data (Organization, ProfessionalService, Service, Article, FAQPage, BreadcrumbList) are generated automatically.

## 6. Quality checks (Phase 5)

Measured on a production build with `NEXT_PUBLIC_REVIEW_MODE=false`, Lighthouse 12 on mobile settings, 18 pages across both languages:

- Accessibility, Best Practices and SEO: 100 on every page
- Performance: 91–97 (the Arabic homepage is the lowest, at 91)
- axe-core (WCAG 2.1 A/AA): no violations, apart from the intentionally faint watermark inside the decorative data-leak mock-up (exempt as incidental text)

Accessibility features: skip link, visible focus states, labelled forms with inline errors, keyboard-operable FAQ tabs, pausable hero animation, `prefers-reduced-motion` respected throughout, `lang`/`dir` on every page, AA contrast on all surfaces.
